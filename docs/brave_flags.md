## How to use these

Brave accepts everything Chromium accepts, plus what is listed here. All switches go directly onto the command line, for example `brave.exe --rewards=debug=true --enable-features=BraveVerticalTabScrollBar --enable-logging=stderr`. Brave’s features use the same `--enable-features` / `--disable-features` syntax as Chromium’s, see [Chromium’s list syntax](chromium_flags.md#how-to-use-these).

Notes:

- `brave://flags` entries are listed next to the switch or feature they control. Toggling them there persists the equivalent switch/feature in `Local State`.
- Feature defaults are compile-time defaults for this Windows build. Brave’s variations service (Griffin, `https://variations.brave.com/seed`) can still change feature states and parameters at runtime; `--disable-field-trial-config`, `--variations-override-country` and `--variations-pr` influence that, and `brave://version` shows active variations.
- Brave appends or rewrites some Chromium switches itself, which can override what you pass: see [Chromium switches that Brave sets or changes](#chromium-switches-that-brave-sets-or-changes).
- `brave.exe` is a GUI application, so logs only appear on a console with `--enable-logging=stderr` (or in a file with `--enable-logging --log-file=<absolute path>`).
- A name being present in the binary means the code that reads it is compiled in. It does not mean the flag is useful, safe or supported. Many switches are developer or test hooks.

## Method

This list was generated from source and then checked against the shipped binaries:

1. Sources: Chromium `156.0.8078.48` with the 778 brave-core `v1.100.23` patches that touch C++ sources applied, brave-core `v1.100.23` itself (including `chromium_src` overrides) and the DEPS repositories that end up in the Windows binaries (V8, ANGLE, Dawn, SwiftShader, Vulkan loader, Skia, FFmpeg, ICU, WebRTC, Perfetto, PDFium, BoringSSL, HarfBuzz, FreeType, libvpx, dav1d). 134 480 C/C++/Rust files were scanned; tests, tools and fuzzers were skipped.
2. Extraction: string constants in `switches` namespaces, every argument of `HasSwitch`/`GetSwitchValue*`/`AppendSwitch*`, `BASE_FEATURE` and its variants (including two-argument features whose name derives from the identifier), `FeatureParam`/`BASE_FEATURE_PARAM`/`GetFieldTrialParam*` definitions, `chrome://flags` entries (Chromium’s and Brave’s `about_flags.cc`) and all environment accessors. Identifiers were resolved by namespace and file proximity.
3. Windows filtering: every line was evaluated with a tri-state preprocessor (`IS_WIN`, x64, official build, no DCHECKs). Code that is certainly not compiled for Windows (other platforms’ `#if` branches and `_mac`/`_linux`/`android/`… files) was dropped; unknown conditions were kept.
4. Binary validation: each remaining name had to occur as a string in `brave.exe`, `chrome.dll`, `chrome_elf.dll` or `chrome_proxy.exe` (plus the bundled graphics DLLs for environment variables) of Brave `156.1.100.23`. Two-argument features are stored as `"kName"`, so that form was matched. Names whose code was dead-stripped by the linker fail this check and are not listed.
5. Precision filters for switches: code of separate executables (installer `setup.exe`, updater, Chrome Remote Desktop, credential provider, Brave’s VPN helper and WireGuard service, standalone tools with their own `main`) was excluded. Constants that are only ever compared against or passed as switch values (like the `--type=gpu-process` process names or `--autoplay-policy` values) and constants that nothing references were dropped. Dynamically named switches (`--env-<service>`) were reconstructed from their call sites.
6. Feature defaults come from the (patched) definitions, including Brave’s `BASE_OVERRIDDEN_FEATURE` rewrites and its edits to `runtime_enabled_features.json5`; the Chromium default, description and line numbers are recovered from the unpatched files.

Split between [brave_flags.md](brave_flags.md) and [chromium_flags.md](chromium_flags.md): an item is Brave’s when all its definitions are in brave-core (including `chromium_src` overrides of Chromium files) or when Brave’s edits to Chromium files introduce it. Everything else is Chromium’s, even when Brave reads or redefines it. Brave’s changes to Chromium items (defaults, Blink runtime feature entries, switches Brave sets at runtime, `brave://flags` entries) are listed in brave_flags.md; chromium_flags.md shows Chromium’s values and links to them.
